# TrackSphere Production-Readiness Audit — 2026-10-04

**Status:** current source of truth. Supersedes `AUDIT.md` (2026-10-03), which is
retained as a historical record but is materially stale: migrations 000005–000018,
`circuitbreaker`, `httpclient`, `sso`, `intel`, `billing`, `mcp.go`, `ecommerce.go`,
five UI pages and the CI workflow all post-date it.

**Method:** four parallel deep-dives (backend security, data/reliability, frontend,
product/strategy/docs), then independent spot-verification of every critical claim
against the code before it was written down. Nothing below is inferred.

**Baseline for this document:** commit `cab6d65` (7 commits, linear, `main`).

---

## 1. Verdict

The architecture is genuinely good — transactional outbox, `FORCE` RLS behind a real
non-superuser role, `SKIP LOCKED` claiming, advisory-locked embedded migrations,
parameterised queries throughout. That foundation is real and was verified, not assumed.

What sat on top of it was not production-ready: **four controls that provably did
nothing while reporting success** (GDPR erasure, the audit trail, the consent
filter, the system-context helper), plus an SSRF proxy, an MFA bypass, and a git
history shipping live session tokens to a public remote. All are fixed in `cab6d65`.

The product remains **operationally immature**: no measurable SLO, no working backup,
a 2000-shipment sweep ceiling, unbounded queries, no mobile navigation, and
documentation that drifts from the code in at least twenty places. Those are Phase 2.
